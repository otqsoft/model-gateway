## Python 3.9 兼容性修复

**问题**：`X | Y` 联合类型语法是 Python 3.10+ 特性，Python 3.9 启动报 `TypeError: unsupported operand type(s) for |`。

**修复范围**（共 9 个文件）：
- `db/database.py`：`_pool: aiomysql.Pool | None` → `Optional[aiomysql.Pool]`，`list[dict]` → `List[dict]`
- `core/utils.py`：`str | bytes | None` → `Optional[Union[str, bytes]]`，`str | None` → `Optional[str]`
- `core/limiter.py`：新增 `from __future__ import annotations` 以兼容模块级小写泛型注解
- `api/v1/chat.py`：`int | None` → `Optional[int]`，`str | None` → `Optional[str]`
- `providers/base.py`、`deepseek.py`、`glm.py`、`minimax.py`、`siliconflow.py`、`modelscope.py`、`xiaomi.py`：
  `ChatCompletionResponse | AsyncGenerator[str, None]` → `Union[ChatCompletionResponse, AsyncGenerator[str, None]]`

**规律**：有 `from __future__ import annotations` 的文件，小写 `list[...]`/`dict[...]` 注解在 3.9 是安全的；但 `X | Y` 运算符本身在运行时求值时仍然报错（即使有 future import），**参数默认值和模块级赋值右侧**不受保护，必须改用 `Optional`/`Union`。

## core/security.py 修复（binascii padding 错误）

**问题**：`ENCRYPT_SECRET_KEY` 未配置时默认为空字符串 `""`，而 `if not secret` 不触发（因为 `""`是假值，实际是触发了），但代码逻辑走到 `base64.b64decode("")` 也会报 Incorrect padding；另外模块级 `_fernet = _get_fernet()` 在导入时立即执行，任何配置异常都会导致启动失败。

**修复**：
1. `secret.strip()` + `if not secret` 正确判空 → 走随机 key 分支
2. base64 解码前补齐 padding：`padded = secret + "=" * (-len(secret) % 4)`
3. 解码失败时 fallback：直接把字符串当原始字节截取 32 位
4. `_fernet` 改为懒加载单例，首次调用 `_get_fernet()` 时才初始化
5. `tuple[str, str, str]` → `Tuple[str, str, str]`（Python 3.9 兼容）
