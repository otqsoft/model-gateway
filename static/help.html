🔑 API 密钥使用说明

Model Gateway 兼容 OpenAI API 接口，可在任何支持自定义 OpenAI 端点的应用中使用

⚡ 快速开始

只需三个参数即可接入，所有兼容 OpenAI 接口的应用通用：

🌐
API 地址 (Base URL)
http://你的网关地址/v1
🔑
API 密钥 (API Key)
sk-你的密钥
🤖
模型名称 (Model)
模型别名
💡 模型名称必须与网关管理页面中配置的模型别名一致，可在管理页面的「模型管理」中查看。
⚠️ API 地址末尾必须包含 /v1，例如 http://192.168.1.100:8080/v1

▶️ Continue (VS Code / JetBrains)

安装 Continue 插件
打开 Continue 配置文件（~/.continue/config.json）
在 models 数组中添加配置：
{
  "models": [
    {
      "title": "My Gateway",
      "provider": "openai",
      "model": "gpt-4",
      "apiBase": "http://你的网关地址/v1",
      "apiKey": "sk-你的密钥"
    }
  ]
}
💡 可添加多个模型条目，每个使用不同的 model 别名，即可在 Continue 中快速切换。

🧩 Dify 插件安装（推荐）

项目内置了 Model Gateway Dify 插件（位于 plugins/dify），安装后 Dify 可自动发现网关中配置的所有模型，无需手动逐个添加。

打包插件 — 在项目 plugins/dify 目录内执行：
# 方式 A：使用 Python 打包脚本（生成 .difypkg）
cd plugins/dify
python pack.py

# 方式 B：用 zip 手动打包
cd plugins/dify
zip -r model-gateway-plugin.zip manifest.yaml main.py pyproject.toml _assets provider models
⚠️ 打包时注意：zip 根目录应直接包含 manifest.yaml，不要多包一层文件夹。避免打入 __pycache__、.venv 等无关文件。
安装插件 — 在 Dify 管理后台进入 设置 → 插件市场 → 本地安装，上传上一步生成的 .difypkg 或 .zip 文件
⚠️ 如果安装时出现 bad signature 签名验证失败错误，需在 Dify 的 .env 中关闭强制签名校验（仅限内网/开发环境）：
FORCE_VERIFYING_SIGNATURE=false
ENFORCE_LANGGENIUS_PLUGIN_SIGNATURES=false
修改后执行 docker compose down && docker compose up -d 重启 plugin_daemon 容器生效。
配置供应商 — 安装成功后，进入 设置 → 模型供应商，找到 Model Gateway 并点击启用，填写配置：
Gateway 根地址
http://192.168.1.10:8000
API Key
sk-你的密钥
🐳 Docker 部署注意：Dify 容器内访问宿主机上的 model-gateway 时，Gateway 根地址请使用 http://host.docker.internal:8000（Linux 可能需额外配置 host 网桥），不要用容器内的 127.0.0.1。
验证并使用 — 点击 验证 确认配置正确，保存后即可在应用编排页面选择网关中的模型
💡 插件预置了 DeepSeek、GLM、MiniMax、小米等常用模型。如需添加更多模型，在 plugins/dify/models/llm/ 下新增 YAML 文件（model 字段须与网关中的模型别名一致），并更新 _position.yaml，重新打包安装即可。

常见安装问题

Q: 安装时提示 PluginDecodeResponse 或无法解析？
通常原因：① 插件包格式过旧（未包含 type: plugin 的 manifest），请用项目 plugins/dify 重新打包；② Dify API 与 plugin_daemon 镜像版本不一致，需对齐版本并全量重启；③ zip 根目录错误，解压后根目录应直接可见 manifest.yaml。
Q: 验证供应商时提示「连接被拒绝」？
检查 Gateway 地址是否正确、服务是否启动。Docker 部署时需使用 http://host.docker.internal:8000 而非 127.0.0.1。

📦 OpenAI SDK

Python

# pip install openai

from openai import OpenAI

client = OpenAI(
    api_key="sk-你的密钥",
    base_url="http://你的网关地址/v1"
)

# 非流式请求
response = client.chat.completions.create(
    model="gpt-4",
    messages=[{"role": "user", "content": "你好"}]
)
print(response.choices[0].message.content)

# 流式请求
stream = client.chat.completions.create(
    model="gpt-4",
    messages=[{"role": "user", "content": "写一首诗"}],
    stream=True
)
for chunk in stream:
    if chunk.choices[0].delta.content:
        print(chunk.choices[0].delta.content, end="")

Node.js

// npm install openai

import OpenAI from 'openai';

const client = new OpenAI({
    apiKey: 'sk-你的密钥',
    baseURL: 'http://你的网关地址/v1'
});

// 非流式请求
const response = await client.chat.completions.create({
    model: 'gpt-4',
    messages: [{ role: 'user', content: '你好' }]
});
console.log(response.choices[0].message.content);

// 流式请求
const stream = await client.chat.completions.create({
    model: 'gpt-4',
    messages: [{ role: 'user', content: '写一首诗' }],
    stream: true
});
for await (const chunk of stream) {
    process.stdout.write(chunk.choices[0]?.delta?.content || '');
}

curl

# 非流式

  -H "Content-Type: application/json" \

🔗 LangChain

Python (LangChain)

# pip install langchain-openai

from langchain_openai import ChatOpenAI
from langchain_core.messages import HumanMessage

llm = ChatOpenAI(
    model_name="gpt-4",
    openai_api_key="sk-你的密钥",
    openai_api_base="http://你的网关地址/v1",
    temperature=0.7
)

result = llm.invoke([HumanMessage(content="你好")])
print(result.content)

Python (LangChain + 流式)

for chunk in llm.stream([HumanMessage(content="写一首诗")]):
    print(chunk.content, end="", flush=True)

📖 API 接口参考

所有接口兼容 OpenAI API 规范，请求时需在 Header 中携带 Authorization: Bearer sk-你的密钥

聊天补全

POST /v1/chat/completions 
{
  "model": "gpt-4",              // 必填，模型别名
  "messages": [                   // 必填，消息列表
    {"role": "system", "content": "你是一个助手"},
    {"role": "user", "content": "你好"}

  "temperature": 0.7,           // 可选，0-2

模型列表

参数类型必填说明

❓ 常见问题

Q: 提示「认证错误」或「Invalid API Key」？
请检查 API Key 是否正确，确保以 sk- 开头且完整复制，没有多余空格。
Q: 提示「模型不存在」？
请确认请求中的 model 参数与网关管理页面中的模型别名完全一致，注意大小写。
Q: 请求超时或连接失败？
  • 检查网关服务是否正常运行
  • 确认 API 地址和端口是否正确
  • 如果是远程访问，检查防火墙是否放行端口
  • 可在浏览器中直接访问网关地址测试连通性
Q: HTTPS 环境下无法连接？
浏览器在 HTTPS 页面中默认不允许请求 HTTP 接口（混合内容限制）。建议为网关配置 HTTPS，或通过 Nginx 反向代理并提供 SSL 证书。
Q: 如何查看 API 调用统计？
登录网关管理页面，在「API 密钥」列表中可查看每个密钥的调用次数、Token 用量和费用统计。
Q: 支持哪些 OpenAI 接口？
目前支持 /v1/chat/completions（聊天补全）和 /v1/models（模型列表），兼容流式和非流式两种模式。
Q: 密钥的限流和配额如何设置？
在管理页面的「API 密钥」编辑中，可设置并发数、每日限额、每月限额、有效期和允许使用的模型范围。
